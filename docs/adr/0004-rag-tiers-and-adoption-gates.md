# 0004 · RAG 分层与引入门

- 状态：Accepted
- 日期：2026-09-23

## 上下文

创作面板（#15）交付后，章节正文生成（#16）必然面临"模型只看本章细纲、不知道前文写过什么"
的一致性问题。2026-09-23 的同类开源项目调研（GitHub 一手核验，星标与许可证均为当时数据）
给出以下事实：

1. 成熟项目（lingfengQAQ/webnovel-writer 约 7.2k★ GPL-3.0、YILING0013/AI_NovelGenerator
   约 6.1k★ AGPL-3.0 等）的共性架构是"章节提交 → 派生多路视图"：每章生成后投影
   state/index/summaries/memory/vector，下一章生成前检索组装上下文。这证明
   **一致性 RAG 是创作链路的主战场，不是可选项**。
2. 上述项目普遍 GPL/AGPL 许可，本项目 Apache-2.0 只能 clean-room 学思想，不能拷代码；
   且它们重度依赖嵌入模型（如 Qwen3-Embedding-8B）与向量库（ChromaDB 等），与本项目
   "无 key、断网可跑、CI 零模型额度"红线（ADR-0002）冲突。
3. 必须区分两类检索，二者版权性质完全不同：
   - **A 学习型**：检索他人小说的拆书产物——版权风险硬，延续 #15 决策：只允许聚合数字与
     受控标签进入提示词，原文与 quote 永不入库、永不注入；
   - **B 一致性型**：检索作者自己正在写的书——无版权问题，是 #16 的核心依赖。
4. v0.1 既定方向：检索第一版为结构化查询 + 中文 bigram BM25，不引入 embedding；
   向量检索与图谱检索均为冻结项，解冻必须凭金标证据而非"感觉更高级"。
5. 维护者单人、每周约 4–6 小时（ADR-0003），常驻向量库/图数据库等重栈的运维成本不可接受。

## 决策

检索能力分四层，**逐层付费、凭证据解冻**：

- **L0 聚合数字（现状，#15 已实现）**：参考书的主题分布、爽点章距、角色出场矩阵等统计量
  注入创作提示词；不含任何原文。
- **L1 bigram BM25 + 确定性上下文包（#17，本 ADR 批准启动）**：
  - 纯 Python 中文 bigram BM25：零 embedding、零外部服务、离线可跑、结果可逐位重算；
  - 索引对象**仅限本书**：章节摘要与情节点（Stage 2 产物）、已 user-confirmed 的
    人设/金手指/细纲、已生成章节的结构化自评元数据；**不索引参考书原文**；
  - 每次生成前确定性组装上下文包：前章摘要 + 角色卡 + 活跃伏笔 + 叙事债
    （已开启未回收的钩子）；
  - 首版必须同步交付**金标集与 Recall@10 基线报告**：以自造 CC0 fixture 构造
    query → 应召回章节的判定，报告 JSON 落盘，作为日后所有检索层的对照基准。
- **L2 向量混合检索（#13 保持冻结）**：仅当 L1 在金标集上 Recall@10 经验证不足时才解冻；
  形态限定为 sqlite-vec 或纯 numpy，禁止 Milvus 一类常驻服务；策略为 auto 选择、
  向量失败确定性回退 BM25、RRF 融合、可选 rerank；上线必须 A/B 对照 L1 金标成绩，
  且无 key/断网时自动退回 L1，离线回环永不破坏。
- **L3 实体图谱 + CHAPTER_COMMIT 事件投影（排在 #4 之后）**：每章生成后投影
  实体/关系/伏笔状态；JSONL 仍为唯一真源，图谱只是派生视图，不改主存储；
  上线必须 A/B 对照，且不改变 L0–L2 的回退链。

**通用引入门**（适用于未来一切检索增强）：

1. 先有金标集与 Recall@10 基线，才允许引入新检索层；无评测数据不得加依赖；
2. Fake-first 不变：任何检索路径必须有离线、可重放的确定性回退；
3. 证据纪律延续 ADR-0002：模型只给 quote 文本、偏移本地锚定；学习型检索永远只出
   聚合数字，不出原文/quote；
4. 新层以可选依赖（extras）引入，默认安装保持零重依赖。

## 后果

- 好处：#16 在不破坏"无 key 可跑"与版权红线的前提下获得前文一致性；每层引入都有量化
  门槛，杜绝凭感觉扩栈；Apache-2.0 合规风险被架构隔离（GPL/重栈方案不进依赖）。
- 代价：bigram BM25 对同义改写与语义近邻召回弱——承认这是已知短板，用金标集量化它
  而非粉饰；"活跃伏笔/叙事债"需要最小结构化字段支撑，#16/#17 要为伏笔建立 schema
  （钩子描述 + 开启章 + 回收章，回收章可空）。
- 放弃的方案：
  - 直接上嵌入向量 + 向量库（违反离线红线、重栈、无对照证据，#13 继续冻结）；
  - 一步到位做知识图谱（#4 的角色/设定档案尚未交付，实体层无真源，排在更后期）；
  - 检索参考书原文辅助写作（版权红线，永不解冻；学习型只保留 L0 聚合数字）；
  - 不做检索、靠模型长上下文硬塞（成本不可控、超出窗口后必然失忆、无法测试）。
