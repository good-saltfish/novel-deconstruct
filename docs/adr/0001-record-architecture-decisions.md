# 0001 · 记录架构决策

- 状态：Accepted
- 日期：2026-09-22

## 上下文

单人项目最容易出现的退化是：决策只存在于对话里，一周后"为什么当初这么做"无法追溯，
然后在同一个岔路口反复横跳。本项目的关键选择（切分是否可用 LLM、产物格式、证据格式、
学习层是否自动生成）一旦写进代码与测试，推翻成本都会随版本增长。

## 决策

采用 Michael Nygard 风格的轻量 ADR：Markdown 文件、顺序编号、只增不改；
任何影响模块边界、数据 schema、外部依赖或项目红线的变更，必须先有 Accepted ADR。
纯实现细节（函数内部写法、局部重构）不需要 ADR。

## 后果

- 好处：决策上下文（尤其被放弃的方案）不丢失；新贡献者可快速理解决策谱系。
- 代价：每个大变更多一份短文档；为控制成本，ADR 限制在"上下文/决策/后果"三节，不写成长文。
- 放弃的方案：只用 commit message 承载决策（信息分散、无法表达被放弃方案）；
  用外部 Wiki（脱离代码、易腐化）。
