# 0005 · 学习型写作知识库（L0.5）：本地资料库的可用边界

- 状态：Accepted
- 日期：2026-09-25
- 关联：[ADR-0004](0004-rag-tiers-and-adoption-gates.md)（RAG 分层）、#15（骨架）、#17（L1）、#21（实现）

## 上下文

作者维护着一个本地写作资料库（如 `d:\myproject\novel-project\网文写作`），
包含：自研拆书拆解/方法论 md、大神写作心得 doc/docx、设定素材、扫榜分析，
以及大量**受版权保护的小说全文与前 40 章原文**。

需求：写大纲与设定时能检索运用资料库里的知识。ADR-0004 的 L0（参考书聚合数字）
覆盖面太窄，L1 明确只检索"本书"，因此需要一条新的检索支线；但该目录里混有版权原文，
"全部入库"会直接违反项目版权红线（开源发布、可能上云模型）。

## 决策

新增 **L0.5 学习型知识库**：把本地资料库中**允许使用的知识**建成离线 BM25 索引，
只服务于**骨架/设定生成**；版权小说全文在入库环节即被硬排除。

### 内容三分类（入库时判定，可审计）

| 类别 | 例子 | 处理 |
|---|---|---|
| A 自研成果 | 抄书拆解/拆书分析/拆解报告/方法论 md | 入库 |
| B 教学与事实资料 | 写作心得 docx、设定素材 txt、扫榜分析 md | 入库 |
| C 小说原文 | "书名 - 作者.txt"、`原文/` 目录、progress.json、大文件、章节体 txt | **硬排除**，写入 manifest 供审计 |

### 硬规则

1. **C 类排除用多重判据**：路径含 `原文` 目录、文件名模式（`* - *.txt`、`*原文*`、
   `前40章*`、`*第*章*.txt`、`*.progress.json`）、**txt** 单文件 >1MB、
   以及章节标题启发式（文本中 `第N章/节/回` 行 ≥ 8 判定为小说正文）。
   章节启发式对**自研分析类文件名**（含 拆解/报告/分析/教程/心得/方法论 等标记）跳过——
   这类文件天然包含章节标题，真实 dogfood 验证过会误伤；md/docx 不适用 1MB 上限
   （分析报告内嵌图片可超过 1MB）。
2. **只索引解析后的知识，不复制源文件**：索引产物在工作区 `kb/` 内，
   含 `index.json`（BM25 语料）与 `manifest.json`（每个文件的收录/排除原因）。
3. **v1 支持 .md/.txt/.docx**：docx 用 stdlib zipfile 解析，零第三方依赖；
   .doc（老二进制格式）跳过并在 manifest 报告，不引重依赖。
4. **检索只接入骨架/设定生成**（cr-v0 prompt 增加"写作方法论参考"区块，标注来源）；
   **章节正文生成（#16）不接入知识库**，正文侧的唯一上下文仍是本书 ContextPack，
   使版权隔离边界在代码结构上成立。
5. 检索器复用 #17 的确定性 bigram BM25；Fake 链路离线可用；
   知识库缺失时生成正常降级（不注入任何参考）。
6. 根目录通过 `ndecon kb index --root <path>` 显式指定（可重复，多根），
   默认值取环境变量 `NOVEL_DECON_KB_ROOTS`；不在开源代码里硬编码个人机器路径。

## 后果

- 好处：大纲/设定阶段可利用作者积累的方法论与素材，且全程离线、来源可审计；
  C 类小说原文即使存在于资料库目录也无法进入索引与 prompt。
- 代价：.doc 老文件 v1 不可用；模式+启发式排除理论上存在误判（通过 manifest 审计兜底，
  后续可加白名单覆盖）；bigram 对语义改写查询偏弱，与 L1 同样的已知短板。
- 放弃的方案：
  - "整个目录无差别入库"——版权原文可能被发送给云端模型，直接违反红线；
  - 一上来就向量化——教学资料虽无版权注入问题，但 ADR-0004 引入门要求先有词法基线
    与真实查询积累，BM25 先行；
  - 给知识库加 Agentic RAG（模型自主决定查什么）——破坏确定性与可审计性，暂不做。
- 解冻路径：使用中积累真实查询后，若知识库检索的词法召回经评测不足，
  可按 ADR-0004 引入门为知识库单独评估 L2（教学资料侧的向量解冻门槛低于正文侧）。
