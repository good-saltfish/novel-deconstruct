# 0002 · 确定性切分与 Fake-first 双轨

- 状态：Accepted
- 日期：2026-09-22

## 上下文

拆书管道的第一环是章节边界，它是全书所有证据偏移的坐标原点：

1. 边界若由 LLM 决定，同一输入在不同模型/温度下会漂移，证据 quote 失效、缓存失效、回归测试无法进行；
2. 开发机网络不稳定、pypi TLS 受阻，且开源使用者不一定有 API key，若管道必须联网才能跑，
   测试与试用门槛都过高；
3. 真实文本里章节标题形态复杂（中文数字、两/千/万、二合一大章、"爸，我饿"式短标题、
   正文行以"第三章……"开头），纯规则需要处理误切与漏切的权衡；
4. dogfood（《我不是戏神》前 40 章）实测：规则方案可做到 40/40 章边界、行号、字数与人工表完全一致。

## 决策

- **章节切分只允许纯确定性 Python**（正则 + 中文数字解析 + 分隔启发式），LLM 永不参与；
- Provider 协议只覆盖语义层（概要、情节点、黄金三章报告），且必须存在可离线运行的 FakeProvider；
- FakeProvider 是规则演示而非 NLP，所有产物标记 `rule:fake`，禁止用于真实效果宣称；
- 受控词表（基调/主题标签）用枚举在 schema 层强制，非法值无法构造；
- 学习层 takeaways 任何 provider 都不得自动填充（不代笔红线）。

## 后果

- 好处：切分可复现、可单测、零成本；断网/无 key 仍可端到端跑通与演示；CI 不依赖模型额度。
- 代价：切分器对非标标题格式可能漏切/误切——以"preamble 显式保留 + 章号连续性告警"兜底，
  宁可告警不可静默丢字；Fake 产物没有真实语义价值，真实 provider 必须另做评测。
- 放弃的方案：
  - LLM 切章（漂移、贵、不可测）；
  - 只做真实 provider、无 Fake（试用门槛高、CI 脆弱）；
  - 自由文本标签（聚合阶段无法统计，错误发现太晚）。
