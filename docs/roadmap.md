## 二、当前最大盲区

**AI 路径从未用真实模型端到端跑过。** 骨架生成、章节正文、Planner Agent 目前只验证了 Fake 确定性路径与传输契约层，OpenAICompatPlanner 没有真实 LLM dogfood。

预期真实模型上会暴露（ADR-0006 已挂账"待真实 LLM dogfood"）：

- JSON 动作协议鲁棒性：工具名乱编、JSON 带 markdown 围栏/多余文字、必填字段缺失
- 循环经济性：12 步上限是否够用、observation 累积是否撑爆上下文（ADR 已注明 token 截断第一版有意未做）
- 检索注入：知识库片段 + ContextPack 拼进 prompt 后的实际长度与命中率
- 输出质量：节拍/设定是否忠于细纲、是否与已确认金手指矛盾

## 三、下一步候选（按推荐优先级）

### A. 真实 LLM dogfood —— 最推荐，几乎零开发量

知识库已喂入 290 文件/34639 块（含创意收集 1–8 共 846 块），面板已可用。用真实供应商（DeepSeek/智谱等）完整走一遍：

1. 面板「模型设置」配 key（仅进程内存）
2. AI 生成骨架 → 3. Planner Agent 补节拍/补设定 → 4. AI 写一章正文

发现一个问题记一个 issue 再修（版权闸门 #27、分析文件名误伤均为真实 dogfood 产物，fixture 造不出来）。

### B. token 成本追踪 —— A 之后顺势做

竞品调研（2026-09-30，9 个主流开源项目横向对比）确认的全网空白：无任何项目提供"每千字成本/每章消耗/上下文压缩收益"。规划：LLMSession 记录每次调用 prompt/completion token 与供应商单价，出每章/每本成本报表。**前置依赖 A**：没有真实调用数据前做是凭空设计。

### C. #4 拆书侧设定/角色档案

Backlog 唯一在册功能项（low）。创作侧设定需求已被 Planner Agent 部分覆盖，优先级取决于近期是否恢复大规模拆书。

### D. 直接推进真实选题（与 A 合并最佳）

以《阴德保险》（保险精算 × 诡异世界，用户专业 B 盘）为试点，在面板端到端跑：建项目 → 骨架 → Agent 扩第 1 章节拍 → 正文生成。知识库注入链路已实测命中（B3 阴德保险卡为 top1），既是 dogfood 也是正事。

**建议路径：A+D 合并执行，B 待 A 暴露真实成本数据后立项，C 视拆书节奏再定。**

## 四、不做什么（已主动放弃，防止范围漂移）

- 正文生成（#16）永不接自主 agent 循环——ContextPack 的确定性与版权边界不可破坏（ADR-0006）
- 不引入常驻向量服务/重依赖，L2 失败必须确定性回退 L1
- 知识库不存版权原文；学习型检索只出聚合数字与方法论片段，不出原文 quote
- 不做多 provider 自动回退、不静默从 AI 降级 Fake——未配置明确 400 引导
- 面板不绑非回环地址、不加外部 CDN
